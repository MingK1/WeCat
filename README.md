## 简介

WeCat 读取当前 Windows 用户本人有权访问的微信 4.x 本地数据，通过 WeFlow CLI 解析联系人、会话、消息和仍可恢复的本地媒体，再建立一份由 WeCat 管理的本地档案。

它主要承担两项职责：

1. **个人关系与自身聊天统计**：从消息数量、时间、参与方式、话题关键词和阶段变化等可复核数据中，帮助用户回看自己与联系人的互动，以及自己的聊天节奏。
2. **长期存储与回忆**：保留聊天记录和可用媒体，支持重复更新、离线阅读、回忆报告和手动导出独立的 WeCat Library。

普通浏览、统计和报告生成均在本机完成，不需要云端 AI。

## 应用职责

### 本地导入与整理

- 识别微信 4.x 的 `xwechat_files`、账号目录或 `db_storage`；
- 通过独立的 WeFlow 进程读取联系人、群聊、会话与消息；
- 优先使用联系人备注，其次使用昵称和原始标识；
- 导入本地头像、图片、视频、语音、表情和文件记录；
- 重复导入时合并已有记录，避免产生重复消息；
- 导入失败或取消时继续保留上一次完整档案；
- 拒绝把不同微信账号的数据合并到同一档案。

### 关系与个人分析

- 最近联系明显增多、重新联系、排名变化和久未联系观察；
- 联系人消息量、活跃天数、最近联系时间和阶段排名；
- 双方发送数量、文字量、表情、图片、视频、语音和文件对比；
- 双方消息占比、主动开启次数和典型回复间隔；
- 小时、星期、月度和年度聊天节奏；
- 个人输出量、活跃联系人、聊天集中度和投入对象变化；
- 可回到原消息的话题关键词、共现词和原文片段；
- 以本人为中心、联系人环绕的关系星图；
- 第一次聊天、最繁忙日期、最长沉默、周年和“那年今日”。

所有统计只描述记录中的可计算现象。消息多不代表关系更重要，WeCat 也不会推断情绪、亲密程度或联系意图。

### 长期回忆与导出

- 使用接近微信桌面端习惯的会话列表和左右聊天气泡阅读记录；
- 生成年份或单会话的离线 HTML 回忆报告；
- 手动导出可脱离微信和 WeCat 使用的 Library；
- 使用 SHA-256 manifest 记录文件校验值、来源和缺失状态；
- 对已被微信清理的媒体明确标记“已缺失”或“未定位”。

## WeCat 不做什么

- 不发送微信消息，也不监控实时聊天；
- 不修改、删除、迁移或修复微信原始数据库；
- 不恢复已经删除的消息或已被清理的媒体；
- 不提供远程访问、云端同步或手机端微信数据读取；
- 不进行情绪识别、人格判断或关系价值评分；
- 不上传聊天记录、数据库密钥或媒体内容到 AI 服务。

## 系统要求

- Windows 10/11 x64；
- 微信 4.x PC 客户端；
- 只处理本人拥有或已经获得明确授权的数据；
- 首次准备解析环境时需要 Node.js 22.13 或更高版本；
- 首次准备解析环境时需要 Python 3.10 或更高版本；
- 可选：FFmpeg，用于在导出 Library 时把 WAV 语音转换为 MP3。

## 安装

1. 打开 [Releases](https://github.com/MingK1/WeCat/releases/latest)。
2. 下载 `WeCat-<version>-Setup.exe`。
3. 运行安装器并选择安装目录。
4. 启动 WeCat。

当前安装包未配置商业代码签名证书。Windows 可能显示未知发布者提示，请只从本仓库 Release 页面下载安装包，并在需要时核对 Release 中公布的 SHA-256。

## 第一次导入

### 1. 选择微信数据目录

打开“导入与更新”，选择以下任意一种目录：

- `xwechat_files` 总目录；
- 当前微信账号目录；
- 当前账号下的 `db_storage` 目录。

点击“检查”，确认 WeCat 已识别到账号和数据库文件。

### 2. 准备数据库访问

如果“微信数据库访问”尚未就绪：

1. 点击“打开初始化终端”；
2. 按终端提示完全退出微信；
3. 只在终端提示后重新启动微信并完成登录；
4. 等待终端验证数据库访问；
5. 回到 WeCat，状态会自动刷新。

初始化终端由 WeCat 在本地生成，但登录、扫码和取钥过程由用户本人操作。WeCat 不会代替用户输入微信凭据。

### 3. 可选：准备语音资产

数据库访问就绪后，可以点击“准备语音明文资产”。该步骤安装轻量 SILK 解码器，使下一次导入能够把仍存在于本地数据库中的语音保存为标准 WAV。

### 4. 开始导入

默认点击“优先导入聊天记录”。该模式先完整保存所有可读取消息，适合首次导入和大型档案。需要同时整理本地媒体时，勾选“同时整理可用媒体”后再导入；这会显著增加耗时和磁盘占用。超过 10,000 条消息的超大会话会自动优先保存聊天记录，跳过高内存媒体扫描。导入完成前，其它页面仍显示上一次完整档案；取消或失败不会破坏它。

## 日常使用

### 总览

总览优先显示最近联系增长、重新联系和排名变化，并展示自己的近期输出量、活跃联系人、文字量和聊天集中度。

### 关系与个人分析

“关系回顾”包含：

- 联系人排序与近期变化；
- 个人关系星图；
- 自己的活跃时段、星期、月度和年度输出；
- 自己对不同联系人的投入占比变化；
- 单个联系人的双方参与、话题、时段、纪录和原文入口。

### 人物与聊天回忆

“人物与群聊”用于查找联系人或群聊，“聊天回忆”用于阅读原始消息。话题片段和统计证据可以定位到具体日期和消息，定位后可以清除日期范围并返回完整聊天。

### 文件与媒体

“文件与媒体”显示每条媒体记录的类型、时间、大小和可用状态。可用文件使用系统默认程序打开。

### 回忆报告

“回忆报告”可以按年份或单个会话生成离线 HTML，并保存到用户选择的位置。

### 更新档案

微信产生新消息后，再次打开“导入与更新”并执行导入。WeCat 会更新现有档案，而不是创建重复副本。

## 统计口径

- “最近”默认指今天及此前 29 个本地日历日；
- 对比期是再之前的 30 个本地日历日；
- 历史月均需要至少 90 天可用历史；
- 去年同期只有在档案覆盖对应时期时才显示；
- 一次对话开启定义为连续沉默至少 12 小时后的第一条消息；
- 典型回复间隔排除超过 7 天的消息间隔；
- 关系排名只比较单聊联系人，不让群聊和系统会话影响排名；
- 话题线索使用本地分词、停用词过滤和同条消息共现，不调用语言模型；
- 文字量按文字消息中的 Unicode 字符计算，不把媒体占位内容算入文字量；
- 样本不足、前期为零或没有同期记录时，界面会显示准确值或“历史不足”，不会显示无限增长率。

## WeCat Library

Library 只能由用户在“文件与媒体”页面手动导出。目录结构如下：

```text
WeCat-Library-YYYYMMDD-HHMMSS/
├─ index.html
├─ manifest.json
├─ chat/
│  └─ <联系人或群聊>-<hash>/chat.html
├─ image/
├─ video/
├─ voice/
├─ sticker/
├─ file/
└─ avatar/
```

- `index.html` 是 Library 总入口；
- `chat/` 中的 HTML 使用相对路径引用媒体；
- 图片、视频、语音、表情、文件和头像保持为普通文件；
- WAV 在本机存在 FFmpeg 时优先转换为 MP3，转换失败则保留 WAV；
- `manifest.json` 记录相对路径、SHA-256、字节数、消息来源、时间和保存状态；
- 已缺失或未能可靠定位的媒体仍会写入 manifest，但不会伪造文件路径；
- 导出先写入 `.partial` 目录，只有全部完成后才发布最终目录。

Library 是便于长期保管和阅读的副本，不应取代原始 `xwechat_files`、系统备份或其它独立备份。

## 本地数据位置

默认数据目录：

```text
%APPDATA%\wecat\
├─ archive\current\          当前完整 WeCat 档案
├─ staging\                  导入临时目录
└─ weflow\
   ├─ home\.weflow-cli\      WeFlow 配置、凭据和 Python 环境
   └─ setup\                  WeCat 生成的初始化脚本
```

卸载 WeCat 不会自动删除 `%APPDATA%\wecat`，以免误删个人档案。需要彻底清除数据时，应先确认已经完成独立备份，再由用户手动处理该目录。

## 隐私与数据安全

- 微信原始目录始终作为只读输入；
- 数据库访问凭据由 WeFlow 保存在隔离的本地配置中，不发送给 React 页面；
- Electron 渲染进程没有直接的 Node.js 或任意文件系统权限；
- 普通浏览、统计、话题线索和报告不发起云端 AI 请求；
- 临时导出目录会在导入成功、失败或取消后清理；
- WeCat 档案包含私人聊天内容，应保护 Windows 账户、磁盘和备份介质；
- 同一 Windows 账户下运行的其它软件通常也能读取该账户有权限访问的本地文件。

## 媒体覆盖与限制

消息记录和媒体文件是不同的数据。即使消息仍然存在，微信也可能已经清理对应的图片、视频、语音或文件。

- `本地可用`：已找到并保存普通本地文件；
- `已缺失`：预期文件路径已经不存在；
- `未定位`：消息表明存在媒体，但没有得到可靠的本地路径；
- 视频只有在消息 MD5 能与本地 MP4 唯一匹配时才保存；
- 语音只有在 SILK 数据仍存在且解码器可用时才能保存；
- WeCat 不会仅凭显示文件名把不确定文件强行匹配到消息。

## 常见问题

### 无法识别微信目录

确认选择的是 `xwechat_files`、具体账号目录或其中的 `db_storage`，并确认当前 Windows 用户拥有读取权限。

### 初始化后仍显示数据库未就绪

完全退出微信，包括系统托盘中的微信进程，然后重新打开初始化终端。只在终端明确提示后启动和登录微信。

### 部分图片或视频打不开

微信可能已经清理本地缓存。WeCat 会保留消息和缺失状态，但无法恢复已经不存在的文件。

### 语音没有被保存

先完成“准备语音明文资产”，再重新导入。原始 SILK 数据已经被微信清理时仍然无法恢复。

### Library 导出失败

选择当前用户拥有写入权限的目录，避免导出到正在被其它程序占用的位置，并确认磁盘空间足够。WeCat 会自动清理失败的半成品目录并避免同名目录冲突。

### 切换了微信账号

WeCat 不允许把两个账号合并进同一档案。当前版本以一个 Windows 用户数据目录对应一个微信账号档案为主要使用方式。

## 本地开发

```powershell
npm install
npm run dev
```

类型检查和生产构建：

```powershell
npm run typecheck
npm run build
```

生成 Windows x64 安装包：

```powershell
npm run build:win
```

安装包生成在 `release/WeCat-<version>-Setup.exe`。`release/`、`out/`、`node_modules/` 和其它本地构建产物不会提交到 Git；正式安装包通过 GitHub Release 分发。

## 代码结构

```text
src/
├─ main/                  Electron 主进程、导入、档案、分析和导出
├─ preload/               类型化 IPC 桥接
├─ renderer/              React 桌面界面
└─ shared/                主进程与界面共享的数据契约
resources/                应用图标和本地解析辅助脚本
```

主要技术栈：Electron、React、TypeScript、ECharts、WeFlow CLI。
